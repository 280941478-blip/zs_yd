# 基础功能配置与验收

默认租户为“默认租户”，默认组织为“默认组织”。初始 admin 为超级管理员；普通用户角色默认无权限，避免新建账号直接获得管理能力。

## 首次验收

1. 使用 `.env` 的随机初始密码登录，修改个人密码。
2. 创建部门、岗位、普通用户、业务角色并关联。
3. 给业务角色分配少量菜单及按钮；切换普通账号确认可见范围，直接访问未授权接口也应拒绝。
4. 分配不同数据范围，在接入数据权限的业务中验证部门数据隔离。
5. 查看登录日志；新增/修改用户后查看操作日志；确认接口日志可查询。
6. 上传文件并下载。默认文件内容存数据库，访问域名来自首次启动时 APP_PUBLIC_URL；公网部署不要保留 localhost。
7. 创建站内信模板，选择管理员用户类型，对自己的测试账号发送；确认消息列表、未读数及已读状态。

## 短信

配置自己的短信渠道、供应商模板 ID，再建立内部模板编码及参数映射。初始化库没有短信渠道/模板，因此不会向真实手机号发送演示短信。仅在明确选择测试号码时执行发送测试，查询发送日志及供应商回执。

## 邮件

配置邮箱账号、SMTP 主机、端口、SSL/TLS及授权码，建立邮件模板，再向自己的测试邮箱发送并检查日志。初始库没有邮箱账号或模板。

## 默认未启用

工作流、支付、商城、AI、采购、企微等不属于基础版后端。第三方登录未配置；短信登录没有渠道时不可用。定时任务默认不启动，若业务需要 Quartz，先导入对应表并开启自动配置。

上游基础菜单中可能含定时任务、监控等扩展入口。根据项目需要配置后使用；发布前可在菜单管理禁用不需要的入口。接口文档默认关闭，可通过 API_DOCS_ENABLED 开启，生产入口 Nginx 不公开 Actuator/Swagger。
