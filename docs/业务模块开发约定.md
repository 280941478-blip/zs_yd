# 业务模块开发约定

项目业务集中到 business 模块，底座功能保留在 framework、system、infra 中。

## 后端位置

```text
backend/cdzs-module-business/
├─ pom.xml
└─ src/main/
   ├─ java/cn/cdzs/module/business/
   │  ├─ controller/admin/home/
   │  │  ├─ BusinessHomeController.java
   │  │  └─ vo/BusinessHomeRespVO.java
   │  ├─ service/home/
   │  │  ├─ BusinessHomeService.java
   │  │  └─ impl/BusinessHomeServiceImpl.java
   │  ├─ dal/dataobject/   # 数据库实体
   │  ├─ dal/mysql/        # Mapper 接口
   │  ├─ convert/          # 对象转换
   │  ├─ enums/            # 业务枚举和错误码
   │  └─ api/              # 跨模块公开接口
   └─ resources/mapper/    # 复杂 SQL 的 Mapper XML
```

已注册到 `backend/pom.xml` 并由 `cdzs-server` 引入，不需要另建启动类。启动类为 `cn.cdzs.server.CdzsServerApplication`。

### 分层职责

- Controller：URL、参数校验、接口权限、调用 Service、统一响应。不直接操作 Mapper。
- Service：Java 接口，声明对外业务方法。不加 `@Service`。
- ServiceImpl：实现接口并加 `@Service`；编写校验、业务规则、Mapper 调用和事务。写操作按需加 `@Transactional(rollbackFor = Exception.class)`。
- Mapper：数据查询与持久化。简单 SQL 使用 BaseMapperX，复杂 SQL 放 XML。
- DO：表字段映射；VO：接口请求与响应。不要让前端直接控制 tenantId、ownerId 等归属字段。

Controller 通过构造器注入 Service **接口**，不依赖 ServiceImpl。按领域分包，如客户业务：

```text
controller/admin/customer/CustomerController.java
controller/admin/customer/vo/CustomerSaveReqVO.java
controller/admin/customer/vo/CustomerRespVO.java
service/customer/CustomerService.java
service/customer/impl/CustomerServiceImpl.java
dal/dataobject/customer/CustomerDO.java
dal/mysql/customer/CustomerMapper.java
resources/mapper/customer/CustomerMapper.xml
```

已有任务示例也已拆分为 `TaskService` + `service/impl/TaskServiceImpl`，可参考其分页、事务、导入导出和数据隔离逻辑。

## 前端位置

```text
frontend/src/
├─ api/business/home/index.ts       # 按领域管理 API 和请求响应类型
└─ views/business/
   ├─ home/index.vue                # 模块入口页
   └─ components/                  # 业务公共组件
```

例如客户模块放 `api/business/customer/index.ts`、`views/business/customer/index.vue`。客户专用组件放 `views/business/customer/components/`；跨业务领域共享组件放 `views/business/components/`。

动态路由白名单已加入 `views/business/**/*.{vue,tsx}`，不需要每增加一个 business 子目录就再改白名单。菜单组件路径写 `business/customer/index`，不带 src/views 和 .vue 后缀。

## 已接通的入口

后端：`GET /admin-api/business/home/get`，权限 `business:home:query`。
前端：`/business/home`，菜单组件 `business/home/index`，组件名称 `BusinessHome`。

它只返回真实的模块说明，不创建虚构业务数据或业务表。V4 迁移增加“业务管理 → 业务首页”菜单，只为默认租户的管理员角色初始化授权。普通角色须手动分配。

后端重启完成迁移后，重新登录刷新菜单。当前前端请求通过既有 request 封装发送，复用 token、tenant-id 和统一错误处理。

## 数据库与消息

业务表变更统一放 `backend/cdzs-server/src/main/resources/db/migration/` 的新增版本 SQL；不要修改已执行的 V1～V4。当前下一个可用版本为 V5，多人开发先协调编号。

需要调用用户、站内信、短信等能力时，按需在 business 的 pom 中引入 system 模块并调用其公开 API，不把业务实现写回 system。避免反向依赖造成循环。

## 验证命令

在 backend 目录执行：

```powershell
mvn -s ../deploy/maven-settings.xml -B -ntp test
```

包含真实 MySQL/Redis 的集成验证从根目录运行：

```powershell
node scripts/verify-integration.cjs
```

该脚本建立独立测试容器，不使用开发库。
