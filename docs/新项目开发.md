# 从基础版创建新项目

> 当前业务目录与分层以 [业务模块开发约定](业务模块开发约定.md) 为准；已新增 V3 命名迁移与 V4 业务入口，新增数据库变更从 V5 起编号。历史 V1/V2 不修改。

## 1. 建立独立项目

当前底座仓库为 https://github.com/280941478-blip/zs_yd ，CDZS 代码基线为 `6aff763`。建议克隆并改为新项目远程：

```powershell
git clone https://github.com/280941478-blip/zs_yd.git my-project
cd my-project
git remote rename origin starter
# 替换为自己的新仓库地址
git remote add origin https://github.com/YOUR_ORG/my-project.git
.\scripts\dev.ps1 init
```

按下一节修改新项目配置后再启动数据库。也可以从模板创建仓库或复制源码目录。不要复制 `.env`、`.git`、node_modules、target、dist、日志、`.upstream`、source 或数据卷。

保留源码许可证。`UPSTREAM.json` 记录上游版本，升级时显式评审，不在每次发布自动拉上游主分支。

## 2. 改项目标识

- 前端标题：`frontend/.env` 中 `VITE_APP_TITLE`。
- 后端应用名：`backend/cdzs-server/src/main/resources/application.yaml` 的 `spring.application.name`。
- 本地环境：运行 `node scripts/init-env.cjs`；修改新项目 `.env` 中的 `COMPOSE_PROJECT_NAME`、`DB_NAME`，有多个项目并行时修改 HTTP/数据库/Redis 端口。
- Jenkins：修改 `deploy/targets.json` 的项目名、镜像仓库、部署目标和凭据 ID。

初期可以保留 `cn.cdzs` 包名，避免无意义的大范围替换；业务代码默认放在 `cn.cdzs.module.business` 下按领域分包。若整体改包名，要同步组件扫描、Mapper 包、SQL 中文件配置的 @class 等字符串。

## 3. 开发业务

默认直接使用已注册的 `backend/cdzs-module-business`，按 Controller → Service 接口 → ServiceImpl → Mapper 分层。前端 API 放 `src/api/business`，页面放 `src/views/business`。详细目录见 [业务模块开发约定](业务模块开发约定.md)。只有需要独立拆分业务域时才新建 Maven 模块；代码生成器产物也要核对目录、分层和权限。

权限接入：
1. 在菜单管理创建目录、页面和按钮，按钮权限采用 `业务:资源:操作`。
2. 前端 `v-hasPermi` 控制按钮展示；后端 `@PreAuthorize("@ss.hasPermission('业务:资源:操作')")` 必须同时校验。
3. 给角色分配菜单权限和数据范围。新建普通角色默认不授予管理权限。
4. 业务表按需接入租户和部门数据权限；菜单隐藏不等于接口鉴权。

前端路由入口已包含 system、infra、example、business 及登录等页面。business 子目录不需要另加白名单；若另建 `src/views/业务名` 时，在 `frontend/src/utils/routerHelper.ts` 的 `import.meta.glob` 白名单加入该目录，否则动态菜单找不到页面。静态隐藏详情页可加到 remaining.ts。

## 4. 接入消息和日志

优先调用 system 模块公开 API，参考 `system/api/notify`、`system/api/sms`、`system/api/mail` 和对应 service 的实际签名。不要直接写消息表。业务提交成功后发送消息；需要重试的业务另建幂等任务，避免数据库回滚后消息已发送。

操作日志使用底座 `@LogRecord`，参考 AdminUserServiceImpl。接口访问日志不替代业务操作日志。对密码、令牌、银行卡等字段不记录明文。

## 5. 初始化与升级

初次安装：Flyway 在空库依次执行 V1～V4，首次后端启动设置管理员密码和文件访问域名。初始化标记位在同一数据库事务中写入，重复启动不覆盖账号。

后续迁移：在 `backend/cdzs-server/src/main/resources/db/migration/` 放置新的版本 SQL。升级前自动备份，后端启动时由 Flyway 自动执行；应用回滚不回退数据库，因此迁移需要向后兼容。详见 [数据库版本管理](数据库版本管理.md)。

开发第一个业务模块时，先参考 [标准业务模块开发](标准业务模块开发.md) 中的示例任务。

`scripts/configure-starter.cjs`、`generate-database.cjs`、`trim-frontend.cjs` 是制作基础版时的维护脚本，新项目正常启动无需执行；重新执行会覆盖对应配置或重生成种子文件。
