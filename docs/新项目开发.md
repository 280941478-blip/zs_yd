# 从基础版创建新项目

## 1. 建立独立项目

将基础版推送到团队模板仓库，后续从模板创建仓库；也可以复制源码目录。不要复制 `.env`、`.git`、node_modules、target、dist、日志、`.upstream`、source 或数据卷。

保留源码许可证。`UPSTREAM.json` 记录上游版本，升级时显式评审，不在每次发布自动拉上游主分支。

## 2. 改项目标识

- 前端标题：`frontend/.env` 中 `VITE_APP_TITLE`。
- 后端应用名：`backend/yudao-server/src/main/resources/application.yaml` 的 `spring.application.name`。
- 本地环境：运行 `node scripts/init-env.cjs`；修改新项目 `.env` 中的 `COMPOSE_PROJECT_NAME`、`DB_NAME`，有多个项目并行时修改 HTTP/数据库/Redis 端口。
- Jenkins：修改 `deploy/targets.json` 的项目名、镜像仓库、部署目标和凭据 ID。

初期可以保留 `cn.iocoder.yudao` 包名，避免无意义的大范围替换；业务代码放在 `cn.iocoder.yudao.module.<业务名>`。若整体改包名，要同步组件扫描、Mapper 包、SQL 中文件配置的 @class 等字符串。

## 3. 开发业务

小型业务可新建独立 Maven 模块并在根 pom 注册，再由 yudao-server 引入；用代码生成器生成基础 CRUD 后补齐业务校验。

权限接入：
1. 在菜单管理创建目录、页面和按钮，按钮权限采用 `业务:资源:操作`。
2. 前端 `v-hasPermi` 控制按钮展示；后端 `@PreAuthorize("@ss.hasPermission('业务:资源:操作')")` 必须同时校验。
3. 给角色分配菜单权限和数据范围。新建普通角色默认不授予管理权限。
4. 业务表按需接入租户和部门数据权限；菜单隐藏不等于接口鉴权。

前端路由构建入口已裁剪为 system/infra 及登录等页面。新增 `src/views/业务名` 时，在 `frontend/src/utils/routerHelper.ts` 的 `import.meta.glob` 白名单加入该目录，否则动态菜单找不到页面。静态隐藏详情页可加到 remaining.ts。

## 4. 接入消息和日志

优先调用 system 模块公开 API，参考 `system/api/notify`、`system/api/sms`、`system/api/mail` 和对应 service 的实际签名。不要直接写消息表。业务提交成功后发送消息；需要重试的业务另建幂等任务，避免数据库回滚后消息已发送。

操作日志使用底座 `@LogRecord`，参考 AdminUserServiceImpl。接口访问日志不替代业务操作日志。对密码、令牌、银行卡等字段不记录明文。

## 5. 初始化与升级

初次安装：Flyway 在空库执行 V1/V2，首次后端启动设置管理员密码和文件访问域名。初始化标记位在同一数据库事务中写入，重复启动不覆盖账号。

后续迁移：在 `backend/yudao-server/src/main/resources/db/migration/` 放置新的版本 SQL。升级前自动备份，后端启动时由 Flyway 自动执行；应用回滚不回退数据库，因此迁移需要向后兼容。详见 [数据库版本管理](数据库版本管理.md)。

开发第一个业务模块时，先参考 [标准业务模块开发](标准业务模块开发.md) 中的示例任务。

`scripts/configure-starter.cjs`、`generate-database.cjs`、`trim-frontend.cjs` 是制作基础版时的维护脚本，新项目正常启动无需执行；重新执行会覆盖对应配置或重生成种子文件。
