# CDZS 命名迁移说明

## 新名称

- 工作目录：`D:\code\cdzs-starter`。
- Java 包名前缀：`cn.cdzs`。
- Maven groupId：`cn.cdzs.boot`；聚合 artifactId：`cdzs`。
- 启动模块：`backend/cdzs-server`。
- 启动类：`cn.cdzs.server.CdzsServerApplication`。
- 业务模块：`backend/cdzs-module-business`。
- 自定义配置前缀：`cdzs.*`。
- 新环境默认 Docker 项目 / 数据库 / 数据库账号：`cdzs-starter` / `cdzs_starter` / `cdzs`。

重新在 IDEA 导入新目录的 `backend/pom.xml`，JDK 17，工作目录设为新目录下的 backend。原目录被 Windows 进程占用，暂留为迁移前工作副本；继续开发请只使用新目录。

## 现有数据保护

这台电脑复制保留原根目录 `.env`，其中现有 Docker 项目名、库名和数据库账号仍沿用旧值，防止切到新的空数据卷。名称变化不影响现有账号密码。新项目运行 init 则使用新的 CDZS 默认名称。

不要单纯为了改名而修改已有数据卷的数据库名或账号。需要物理数据库、Docker 项目改名时，应另行备份、导出导入及验证。

V1/V2 SQL 按原字节保留，避免 Flyway 校验失败。V3 更新数据库文件配置中的旧类名前缀和默认 OAuth 客户端名称；V4 建立业务模块入口。旧类名的 Redis 类型元数据通过兼容解析映射到新类名，不替换普通用户字符串。

## 保留的上游标识

许可证、原作者署名、UPSTREAM.json、真实上游链接、历史 SQL / 上游 SQL 参考、迁移兼容代码保留旧标识。它们不代表当前运行的模块或品牌仍使用旧名称，也不应随意替换成不存在的来源链接。

## 升级注意

- 本次是命名空间变更，旧的 Java 序列化类型、配置中心键和自定义扩展如引用旧类名，需同步检查。
- 启动前先备份数据库，新旧后端不要同时使用同一个库运行。
- 已有 Flyway 历史的环境正常迁移，不需要打开 STARTER_BASELINE_EXISTING。
- 部署到远端前同步 Jenkins targets.json、镜像名称和各环境配置；已有服务器数据卷继续复用还是另行迁移需明确选择。
- 根目录 Git 远程仍是原来的 zs_yd 仓库，不擅自重命名 GitHub 仓库。
