# CDZS 项目拉取与首次使用教程

适用对象：第一次拿到本仓库的开发人员。按本文完成后，可以在自己电脑登录系统，并开始编写业务代码。

仓库：https://github.com/280941478-blip/zs_yd  
文档更新：2026-09-29。以下使用 Windows PowerShell，示例目录为 `D:\code\cdzs-starter`。

## 1. 先准备环境

| 工具 | 要求 | 用途 |
|---|---|---|
| Git | 可在终端执行 | 拉取代码 |
| JDK | 17 | 编译运行后端 |
| Maven | 3.9.x | 管理 Java 依赖 |
| Node.js | 20.19+，建议 22.x | 前端及初始化脚本 |
| pnpm | 10.33.0 | 安装前端依赖 |
| Docker Desktop | 已启动，使用 Linux 容器 | 运行本地 MySQL、Redis |
| Docker Compose | v2 | 编排容器 |
| IDEA | Java 开发工具 | 后续运行、调试后端 |

在 PowerShell 逐条执行：

```powershell
git --version
java -version
mvn -v
node -v
pnpm -v
docker version
docker compose version
```

`java -version` 和 `mvn -v` 中的 Java 都应为 17。Docker 应能显示服务端信息，不能只有客户端信息。某个命令不存在时，先安装对应工具并配置 PATH，再重新打开终端。

已安装 Node 但没有 pnpm 时：

```powershell
npm install -g pnpm@10.33.0
```

不需要单独安装本地 MySQL、Redis，也不需要向项目维护人索取数据库密码；默认流程会创建自己电脑上的独立环境。

## 2. 拉取代码

先创建或进入自己存放代码的目录，再执行：

```powershell
cd D:\code
git clone https://github.com/280941478-blip/zs_yd.git cdzs-starter
cd .\cdzs-starter
git status
```

如果仓库为私有仓库，先确认自己的 GitHub 账号已有读取权限，按 Git 提示完成认证。

后续命令默认从 `D:\code\cdzs-starter` 根目录执行。根目录应能看到 `README.md`、`backend`、`frontend`、`scripts`、`deploy`。后端聚合 `pom.xml` 在 **backend 目录内**。

已有同名目录时不要直接覆盖；进入已有仓库更新，或换一个空目录克隆。

## 3. 生成自己的本地配置

```powershell
.\scripts\dev.ps1 init
```

成功后根目录生成 `.env`，其中数据库、Redis 和管理员初始密码均为随机值。

- `.env.example` 是配置模板；实际使用的是根目录 `.env`。
- `.env` 不提交 Git，也不要发给其他人。
- 重复执行 init 会保留已有 `.env`，不会重新生成密码。
- 普通首次使用保持默认值即可；不需要手工导入 SQL。

如果 PowerShell 提示禁止执行脚本，可先直接执行等效初始化命令：

```powershell
node scripts/init-env.cjs
```

后续 PowerShell 脚本仍被限制时，按组织策略允许该脚本运行，或使用本文第 9 节的 Git Bash 命令。

### 常用配置的含义

| 根 `.env` 配置 | 默认值或来源 | 说明 |
|---|---|---|
| COMPOSE_PROJECT_NAME | cdzs-starter | Docker 项目和数据卷归属 |
| DB_NAME / DB_USER | cdzs_starter / cdzs | 本地数据库和用户 |
| DB_PASSWORD / MYSQL_ROOT_PASSWORD | init 随机生成 | 数据库密码 |
| DB_HOST / DB_PORT | 127.0.0.1 / 13306 | 本机后端连接 MySQL |
| REDIS_HOST / REDIS_PORT | 127.0.0.1 / 16379 | 本机后端连接 Redis |
| REDIS_PASSWORD | init 随机生成 | Redis 密码 |
| ADMIN_INITIAL_PASSWORD | init 随机生成 | 首次建库时的 admin 密码 |
| APP_PUBLIC_URL | http://localhost:8080 | 首次初始化文件访问地址 |
| STARTER_BASELINE_EXISTING | false | 新库保持 false |

已有数据库后，修改 `.env` 的初始密码不会重置账号密码；修改数据库密码也不会自动更新数据库内用户。不要通过删除数据卷解决登录问题。

开发模式前端端口由 `frontend/.env` 的 `VITE_PORT` 控制；根 `.env` 的 `HTTP_PORT` 用于容器模式入口。第一次使用建议都保留默认 8080。

## 4. 启动数据库和 Redis

确保 Docker Desktop 已启动，然后执行：

```powershell
.\scripts\dev.ps1 infra
```

查看状态：

```powershell
docker compose --env-file .env -f deploy/compose.yml -f deploy/compose.dev.yml ps
```

MySQL、Redis 应处于运行且健康状态。首次需要下载镜像，耗时取决于网络。

若端口 13306 或 16379 已被占用，在首次启动前修改根 `.env` 中对应端口，再执行 infra。不要停止不属于本项目的数据库服务。

## 5. 启动后端

打开一个独立 PowerShell 窗口：

```powershell
cd D:\code\cdzs-starter
.\scripts\dev.ps1 backend
```

脚本会先用 Maven 打包，再运行后端。首次下载依赖可能较慢；看到 BUILD SUCCESS 只说明打包成功，还需要等待应用启动完成。

后端第一次启动会自动建表、执行 Flyway 迁移并初始化管理员和菜单。当前基础版包含 V1～V4，后续版本可能继续增加。

在另一个终端验证：

```powershell
Invoke-RestMethod http://localhost:48080/actuator/health
```

返回状态 `UP` 表示后端健康。保持后端终端运行；关闭或按 Ctrl+C 会停止后端。

## 6. 启动前端并登录

再打开一个 PowerShell 窗口：

```powershell
cd D:\code\cdzs-starter
.\scripts\dev.ps1 frontend
```

脚本会安装依赖并启动 Vite。浏览器访问：

**http://localhost:8080**

| 登录项 | 填写内容 |
|---|---|
| 租户 | 默认租户 |
| 账号 | admin |
| 密码 | 自己电脑根 `.env` 中的 ADMIN_INITIAL_PASSWORD |

密码在本地编辑器查看即可，不需要贴到聊天或提交到仓库。如果此前已在系统修改过密码，请使用修改后的密码。

登录后做一次简单验收：

1. 首页及系统管理菜单能够打开。
2. “业务管理 → 业务首页”显示业务模块说明。
3. “开发示例 → 示例任务”可以创建、查询一条自己的测试记录。
4. 测试文件上传和下载，确认文件访问地址正常。

短信、邮件需要另外配置服务商，首次本地启动不要求接通这些能力。

## 7. 使用 IDEA 调试后端

先在命令行后端窗口按 Ctrl+C，避免重复占用 48080；MySQL、Redis 和前端保持运行。

1. IDEA 选择打开 `D:\code\cdzs-starter\backend\pom.xml`，作为 Maven 项目导入。
2. 已打开整个仓库时，对 backend/pom.xml 选择“添加为 Maven 项目”。不要导入 `.flattened-pom.xml`。
3. Project SDK、Maven Importer JDK、Runner JRE 均使用 JDK 17。
4. Maven settings 可指定 `D:\code\cdzs-starter\deploy\maven-settings.xml`。
5. 重新加载 Maven 项目，等待依赖解析完成。
6. 创建 Application 或 Spring Boot 启动项，按下面填写。

| 启动配置 | 值 |
|---|---|
| Main class | cn.cdzs.server.CdzsServerApplication |
| Classpath module | cdzs-server 对应主模块 |
| Working directory | D:\code\cdzs-starter\backend |
| Program arguments | --spring.profiles.active=starter |
| JRE | JDK 17 |

从 backend 工作目录启动会读取 `../.env`，不需要把数据库密码再填一遍。点击 Run 或 Debug 后，再次验证健康接口。

## 8. 业务代码写在哪里

| 内容 | 目录 |
|---|---|
| 后端业务模块 | backend/cdzs-module-business |
| Java 业务根包 | cn.cdzs.module.business |
| 前端业务页面 | frontend/src/views/business |
| 前端业务 API | frontend/src/api/business |
| 数据库迁移 | backend/cdzs-server/src/main/resources/db/migration |

后端按 **Controller → Service 接口 → ServiceImpl → Mapper** 分层；按 customer、order 等实际领域分包。business 模块已注册，不用再创建一套启动类或重复添加依赖。

前端例如 `views/business/customer/index.vue`，菜单组件填写 `business/customer/index`。business 的路由白名单已配置。增加菜单后给角色授权，并为后端接口配置权限校验。

新增表使用新的 Flyway SQL 版本，当前基线下一版本是 V5；开发前先检查仓库最新编号，避免多人冲突，不修改已执行的迁移。

完整约定见 [业务模块开发约定](业务模块开发约定.md)，实际 CRUD 参考 [标准业务模块开发](标准业务模块开发.md)。

## 9. 每天怎么开、怎么关

日常启动与首次启动相同，不需要重复建库：

```powershell
cd D:\code\cdzs-starter
.\scripts\dev.ps1 infra
```

然后分别启动后端和前端，或用 IDEA 启动后端。需要停止时：

1. 前后端各自终端按 Ctrl+C；IDEA 后端点击停止。
2. 回到根目录执行：

```powershell
.\scripts\dev.ps1 stop
```

stop 停止容器，保留数据。不要执行 `docker compose down -v`，它会删除数据卷。

Git Bash / Linux 可用对应脚本（在项目根目录执行）：

```bash
bash scripts/dev.sh init
bash scripts/dev.sh infra
# 后端与前端分别在两个终端执行
bash scripts/dev.sh backend
bash scripts/dev.sh frontend
# 停止原生前后端后，停止容器
bash scripts/dev.sh stop
```

若只想演示、不调试代码，也可以从根目录执行 `dev.ps1 all` 使用全容器模式。运行前先停止原生前后端，避免端口冲突及两套后端连接同一数据库。详细步骤见 [完整使用教程](底座使用与启动配置教程.md)。

## 10. 后续如何更新代码

先查看自己是否有未提交修改：

```powershell
git status
```

有修改时先按团队流程提交或妥善保存；不要强行覆盖。工作区干净后：

```powershell
git pull --ff-only origin main
```

更新涉及 Java 或数据库迁移时，重启并重新构建后端；前端依赖变化时重新执行 frontend 脚本。已有重要数据应先按 [备份与恢复教程](部署备份与恢复.md) 备份，再执行带数据库迁移的升级。

根 `.env` 不随 Git 更新，新增配置请对照 `.env.example` 补充，保留自己环境的凭据。无需每次修改管理员初始密码。

如果用于一个全新的业务项目，请按 [新项目开发](新项目开发.md) 切换自己的远程仓库并配置独立项目名、库名和端口，再首次启动。多个项目同时运行，还需分别配置后端端口和前端代理，不能只修改目录名称。

## 11. 常见问题

| 现象 | 优先检查 |
|---|---|
| 拉取失败 | 仓库权限、GitHub 网络连通性、Git 认证 |
| IDEA 没有运行按钮 | 是否导入 backend/pom.xml，SDK 是否为 17，Maven 是否导入完成 |
| Maven 下载失败 | 错误中的依赖地址、网络以及 deploy/maven-settings.xml；修复后重试 |
| 后端数据库连接失败 | Docker 容器是否健康、根 .env 是否存在、端口及密码是否匹配 |
| 登录密码错误 | 是否已初始化过数据库或改过密码；修改初始密码配置不会重置数据库密码 |
| 前端打开但接口失败 | 后端健康接口、浏览器 Network、后端实际错误日志 |
| 新菜单看不见 | 当前角色是否授权，迁移是否成功，重新登录刷新菜单 |
| 上传后下载失败 | APP_PUBLIC_URL 与“基础设施 → 文件配置”的已存储域名是否符合实际入口 |
| 端口被占用 | 是否同时启动了命令行后端、IDEA 后端或全容器模式 |

向维护人员反馈问题时提供：执行的命令、失败步骤、错误信息、Java/Node 版本；不要发送 `.env`、密码、Token 或带凭据的完整日志。
