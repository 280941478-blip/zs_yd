# 部署、备份和恢复

## 发布前配置

1. 新建独立 Git 仓库并推送底座。
2. 在 `deploy/targets.json` 配置镜像仓库、SSH 服务器、部署目录和凭据 ID。
3. Jenkins 配置 Docker 构建节点以及 Pipeline Utility Steps、SSH Agent、Credentials Binding、JUnit 插件。
4. 在目标服务器部署根目录放置 `.env`，权限设为 `600`，填写正式数据库、Redis、初始密码和外网地址。
5. 服务器提前登录私有镜像仓库；SSH 主机指纹使用 known_hosts 凭据。
6. 首次先执行 `BUILD_ONLY`，再执行测试环境 `DEPLOY / all`。

现有 Jenkins 流水线增加了部署脚本测试、真实 MySQL/Redis 集成测试以及 JUnit 报告。新底座的 Jenkinsfile 与原采购项目配置互不关联。

## 自动备份

已有发布版本进行后端或全量升级时，在启动新版本、执行新迁移之前自动备份。备份失败则终止升级。首次空库安装没有旧数据可备份；接管已有数据库时须先手工备份。

Linux 示例：

```bash
bash /data/yudao-starter/releases/v1/deploy/backup.sh /data/yudao-starter
```

输出到部署根目录 `backups/mysql-UTC时间-PID.sql.gz`，同时生成 SHA256 校验文件。使用 InnoDB 一致性快照，包含表、数据、触发器、事件和存储过程。备份进程与文件使用独立锁和限制权限，密码不写入命令参数。

默认成功备份后清理超过 14 天的备份，可用 `BACKUP_RETAIN_DAYS=30` 调整。本机备份不能抵御服务器丢失；生产环境还需复制到独立主机或对象存储，并保护备份中的敏感数据。数据库文件存储包含在 SQL 中；切换对象存储后，附件对象必须另外备份。Redis、`.env`、对象文件不在 MySQL 备份中。

可由运维配置每日备份计划；本次不会替你在生产服务器添加定时任务。

## 无损恢复演练

```bash
bash deploy/restore-check.sh /data/yudao-starter/backups/mysql-具体时间.sql.gz
```

先校验 SHA256 和 gzip，再创建无网络、无宿主机端口的临时 MySQL，恢复 SQL，检查默认管理员和安装标记。结束自动删除临时容器及临时数据卷。该命令不会写入原数据库。

## 真实数据库恢复（维护窗口）

仅应用有问题时优先使用 `rollback.sh` 回退镜像。确需回退数据时：

1. 停止外部写入，选定备份及与其兼容的应用版本。
2. 先执行上述恢复演练，核对关键业务数据。
3. 执行以下显式替换命令，最后一个参数必须匹配 `.env` 中的项目名：

```bash
bash deploy/restore.sh /data/yudao-starter \
  /data/yudao-starter/backups/mysql-具体时间.sql.gz \
  --replace-database=yudao-starter
```

脚本锁定部署、停止前后端、再备份当前数据库，然后删除并重建该项目数据库、导入备份。**这会替换现有数据**；失败时应用保持停止，避免继续写入半恢复状态。恢复后也不会自动启动应用。

4. 核对表、账号、关键业务记录及 Flyway 版本，清理这个项目的过期应用缓存；不要清理共享 Redis 的其他项目数据。
5. 使用兼容的发布目录启动应用。旧备份搭配新镜像可能再次执行升级，恢复前必须确认目标版本。
6. 验证登录、权限、业务数据、文件下载，再恢复入口流量。

## 本地部署演练

`scripts/verify-deployment.sh` 在独立 Compose 项目中用已构建的 JAR/dist 制作测试镜像，验证首次部署、后端升级、自动备份、应用回滚、数据保留和隔离恢复。需要 Linux、Docker CLI、bash、flock、gzip、coreutils。不会访问生产服务器。

演练结束后，可使用 `scripts/verify-restore.sh <演练目录> <演练备份路径>` 单独验证显式恢复脚本。它只接受 `verification-deploy-*` 目录和 `starter-verify-*` 项目，并拒绝操作仍在运行的演练环境。

测试镜像直接使用构建产物，因此该演练不等于完整 Jenkins 在线构建验证；实际远程 SSH、仓库推送、TLS 和正式域名必须在提供环境配置后再联调。

生产默认每次拉取镜像。离线演练可使用 `DEPLOY_PULL_POLICY=missing` 复用已有不可变版本镜像，不使用 latest。
